# API contract

Base path `/api/v1`. Browser requests use same-origin HTTP-only authentication cookies. Login is public; other business routes require authentication. Mongoose identifiers are returned as `id`. Lists are paginated as `{items,total,page,pages}` unless an endpoint documents an aggregate.

See the running machine-readable schema at `/api/v1/openapi.json` and Python `/openapi.json`. `/api/v1/docs` points to the backend schema. The schema and endpoint validation are authoritative for request details.

| Area               | Routes                                                                                        |
| ------------------ | --------------------------------------------------------------------------------------------- |
| Authentication     | `POST /auth/login`, `GET /auth/me`, `POST /auth/logout`, `POST /auth/password`                |
| Applications       | `GET/POST /applications`, `GET/PATCH/DELETE /applications/:id`                                |
| Workflow           | `POST /applications/:id/submit`, `/assess`, `/decision`, `/withdraw`                          |
| Assessments        | `GET /assessments`, `POST /predictions`, `POST /explanations`                                 |
| Analytics          | `GET /analytics`, `GET /portfolios`                                                           |
| Scenarios          | `GET/POST /scenarios`, `DELETE /scenarios/:id`                                                |
| Batch jobs         | `GET/POST /batches`, `GET /batches/:id`, `GET /batches/:id/download`, `POST /batches/preview` |
| Alerts             | `GET /alerts`, `POST /alerts/:id/acknowledge`, `/resolve`                                     |
| Model metadata     | `GET /model`, `GET /monitoring`                                                               |
| Reports            | `GET /reports/:type?format=pdf\|csv\|xlsx&id=...`                                             |
| Audit              | `GET /audit`                                                                                  |
| Administration     | `GET/POST /users`, `PATCH /users/:id`, `GET/PATCH /settings`                                  |
| Grounded assistant | `POST /copilot`                                                                               |

The backend `/health` verifies MongoDB and inference availability. It returns 503 when either required service is unavailable. Python `/health` verifies the model is loaded.

Application numeric fields include `monthlyIncome`, `monthlyExpenses`, `existingDebt`, `existingEmi`, `creditScore` (optional 300–900), `loanAmount`, `tenureMonths`, `interestRate` (annual percent), `employmentMonths`. Identity/metadata fields include `applicantName`, `applicantId`, `age`, `employmentType`, `loanPurpose`, `currency`. Draft validation permits incomplete inputs; submission enforces the complete schema. Do not send model-risk band, approval state or internal database operators to application creation.

Roles: Administrator can administer and perform operational work; Risk Analyst can create, update and assess; Reviewer can record decisions and reasons; Read-Only Viewer can read but cannot mutate or export protected data. Server-side role checks remain effective if a user calls a hidden endpoint directly.

Errors use meaningful HTTP status codes (400 validation, 401 authentication, 403 permissions, 404 missing entity, 409 lifecycle conflict, 429 limits, 502/503 upstream inference) and a structured error message with request correlation ID. Predictions fail gracefully when the model is unavailable; no synthetic fallback prediction is generated by JavaScript.
